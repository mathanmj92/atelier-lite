# Contributing

Thanks for helping with Atelier Lite. The repository is private for now, so this is for people who have been given access.

## Getting started

```
npm install
npm run sync
npm start
npm test
```

Node.js 20 or newer on Windows 10 or 11. `npm run dist:win` builds the installer into `release/`.

## Before you open a pull request

1. Make one focused change. A bug fix and a new feature belong in separate pull requests.
2. Run `npm test` and start the app once with `npm start` to see the change work.
3. If you change something users can see, add a line under **Unreleased** in [`CHANGELOG.md`](CHANGELOG.md) and update [`docs/USER_GUIDE.md`](docs/USER_GUIDE.md) if it affects how the app is used.
4. Bug fixes need a test where the code can be tested without a window (see `tests/`). For window behaviour, say how you checked it.

## Code style

- Match the file you are editing: naming, comment density and idiom. Comments say why, not what.
- Plain JavaScript, no build step for `electron/`, `shell/` or `shim/`.
- Text in the app is written for everyone, including people who are not used to computers: short sentences, plain words, and no jargon.
- Keep the app light. It must stay usable on an older PC with 4 GB of memory; avoid anything that runs constantly in the background.
- Do not add network calls. The app works offline, and the only traffic is to the AI engine the user has chosen.

## What not to change here

The bundled apps in `apps/` are generated by `npm run sync` from their own projects. Fix them at the source and sync again, rather than editing the copies. Their licences must stay in their folders.

## Reporting problems

Open an issue using the templates, or use **Help, Report a problem** inside the app. Include the version (Help, About), what you did, what you expected and what happened. Never attach documents that contain private information.

For security problems, follow [`SECURITY.md`](SECURITY.md) instead of opening a public issue.
